# Backlog

The persistent source of truth for all pending work. This is the "waiting room" —
items live here until they're pulled into a daily file as a realistic commitment.

**Daily files are commitments. This backlog is everything else that still needs a home.**

Guidelines:
- Every deferred or not-yet-scheduled task belongs here (so nothing gets dropped).
- Team commitments (things you owe other people) must NEVER be silently dropped.
- When an item is pulled into a daily file and completed, remove it from here.
- Review weekly to reprioritize and clear stale items.

---

## Decisions Needed
Items requiring a decision before work can proceed. Often these block other work.

- [ ] (example) Decide whether to use approach A or B for the data migration

---

## Recurring Reviews (Behind Schedule)
Project reviews that have fallen behind their cadence. Populated from `./bin/wip review-projects`.

- [ ] (example) Review Example Project Alpha (8 days behind, cadence: weekly)

---

## Team Communication
Messages, updates, or responses owed to others.

- [ ] (example) Reply to Jane about the API design proposal

---

## Technical Debt
Long-running items needing dedicated time.

- [ ] (example) Refactor the legacy notification module

---

## Project-Specific
Items tied to specific projects but not yet scheduled.

- [ ] (example) [Project Alpha] Draft the phase-2 rollout plan

---

## Low Priority / Someday
Items to revisit when there's capacity. No urgency.

- [ ] (example) Explore a better template for weekly reviews

---

## Recently Completed
Completed items kept for reference. Cleared monthly.

- [x] (example) Set up the WIP repository
